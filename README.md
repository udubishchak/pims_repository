# PIMS — Прототип СППР для управления запасами сети чайных

Программный код прототипа системы поддержки принятия решений (СППР)
для прогнозирования расхода ингредиентов и формирования рекомендаций
по закупкам. Разработан в рамках ВКР бакалавра по программе
«Бизнес-информатика», ИШБ НИУ ВШЭ, 2026.

> **Полная описательная часть** — в тексте ВКР (главы 1–3).
> Настоящий репозиторий соответствует Приложению Б.

---

## 📌 Краткое содержание проекта

PIMS — российская сеть чайных, использующая iiko как учётную систему.
Текущий процесс управления запасами полностью ручной: менеджер тратит
≈10 ч/нед на расчёты, регулярно возникают стоп-листы (7,3% дефицитных
наблюдений) и списания (≈170,4 тыс. руб./год на одну точку).

Прототип реализует **«интеллектуальную надстройку» над iiko**, которая
автоматически прогнозирует расход 30 ингредиентов и формирует
рекомендации по закупкам с учётом срока хранения, MOQ, дедлайнов и
двух каналов поставки.

### Ключевые результаты

| Метрика | Значение |
|---|---|
| **WAPE** прогнозной модели (LightGBM, квантильная регрессия) | **12,8%** |
| **Бэктест** (5 фолдов, expanding window) | 13,4% ± 0,9 п.п. |
| **Калибровка** квантилей q80 / q90 / q95 | отклонение ≤ 3 п.п. |
| **ROI** базового сценария (на маржинальной прибыли + замещение) | **112%** |
| **Срок окупаемости** прототипа на 1 точке | **5,7 мес.** |

│   ├── dag2_evening.py             # 18:00 — лёгкое обновление
│   └── dag3_deadline.py            # 19:30 — алерт на кассу

│   ├── test_newsvendor.py          # MOQ, pack_size, 3 случая newsvendor
│   └── test_etl.py                 # smoke-тесты загрузки
├── docker-compose.yml              # postgres + airflow + notifier
├── requirements.txt                # Python-зависимости
└── LICENSE                         # MIT

## 🧠 Соответствие модулей разделам ВКР

| Модуль | Раздел ВКР | Что реализует |
|---|---|---|
| `etl_pipeline.py` | 3.2.1 | Extract → Transform → Load с UPSERT по `(location_id, product_id, date)` |
| `deficit_detector.py` | 2.4.4, 3.2.2 | Правило `stock_ratio < 0,15 И demand_drop > 0,50` |
| `feature_builder.py` | 3.3.1 | 23 признака: лаги, скользящие, календарь, погода, промо |
| `train_lightgbm.py` | 3.3.2 | LightGBM с квантильной регрессией для α ∈ {0,5; 0,8; 0,9; 0,95} |
| `generate_recommendations.py` | 3.4.1–3.4.3 | Единое правило выбора квантиля (3 шага) + newsvendor + MOQ |
| `metrics.py` | 3.3.3 | WAPE/MAE/RMSE + калибровка q80/q90/q95 + эксперимент с погодой |
| `notifier.py` | 3.4.4 | FastAPI-сервис: `/check_deadline`, `/order_sent`, `/recalculate` |
| `dag1_morning.py` | 3.1.1 | DAG-1 07:00 МСК: ETL → переобучение → рекомендации |
| `dag2_evening.py` | 3.1.1 | DAG-2 18:00 МСК: пересчёт прогноза с обновлёнными продажами |
| `dag3_deadline.py` | 3.1.1, 3.4.4 | DAG-3 19:30 МСК: проверка факта отправки заказа |

## ⚙️ Быстрый старт

### Локальный запуск через Docker Compose

```bash
git clone https://github.com/<your-username>/pims-inventory.git
cd pims-inventory
docker compose up -d
```

После запуска:
- **PostgreSQL** — `localhost:5432` (DB: `pims`, user: `pims`, password: `pims`)
- **Airflow UI** — http://localhost:8080
- **Notifier API** — http://localhost:8001/docs (Swagger)

### Запуск тестов

```bash
pip install -r requirements.txt
pytest tests/ -v
```

### Ручной запуск отдельного шага

```python
from src.etl_pipeline import ETLContext, run as run_etl
from pathlib import Path
import pandas as pd

ctx = ETLContext(
    location_id=1,
    run_date=pd.Timestamp.today(),
    data_dir=Path("data/samples"),
    db_url="postgresql://pims:pims@localhost/pims",
)
run_etl(ctx)
```

## 📐 Архитектура (5 уровней)

```
┌─────────────────────────────────────────────────────────┐
│  1. ИСТОЧНИКИ:  iiko XLSX │ Yandex Weather │ MarketCal  │
└────────────────────────────┬────────────────────────────┘
                             ▼
┌─────────────────────────────────────────────────────────┐
│  2. ETL:  Apache Airflow  (DAG-1, DAG-2, DAG-3)         │
└────────────────────────────┬────────────────────────────┘
                             ▼
┌─────────────────────────────────────────────────────────┐
│  3. ХРАНИЛИЩЕ:  PostgreSQL  (multi-location PK)         │
└────────────────────────────┬────────────────────────────┘
                             ▼
┌─────────────────────────────────────────────────────────┐
│  4. МОДЕЛЬ:  LightGBM × 4 квантильные модели + Newsvendor│
└──────────────┬──────────────────────────────┬───────────┘
               ▼                              ▼
┌────────────────────────┐    ┌─────────────────────────────┐
│ 5а. DataLens (просмотр)│    │ 5б. FastAPI + iiko Front    │
│     3 экрана           │    │     (транзакционные действия)│
└────────────────────────┘    └─────────────────────────────┘
```

**Принципиальное разделение:** Yandex DataLens — **только для просмотра**
рекомендаций и аналитики. Все транзакционные действия (фиксация факта
отправки заказа, корректировка количеств, уведомление о дедлайне)
выполняются через FastAPI-сервис и плагин iiko Front.
